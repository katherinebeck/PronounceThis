# RCA — Deploy run c9ac00d4-e617-4df2-b666-4a170ab642cd (accent-coach-pro)

## Summary
Redeploy failed at the **build_image** step. The backend `pip install` could not resolve the pinned dependency `torch==2.14.1+cpu`. This is a source-level problem in `backend/requirements.txt`, not a manifest/platform issue.

## Failed step
`build_image` (Cloud Build `b74b17a0-ba8c-4fc8-8e4e-98136a39cd3f`), step #2 `docker-build`, `backend-build` stage. Retried 3× by the build's retry wrapper, all failed, then CANCELED the frontend build and exited non-zero.

## Evidence (build log)
```
ERROR: Could not find a version that satisfies the requirement torch==2.14.1+cpu
       (from versions: 1.13.0 ... 2.14.0, 2.14.1)
ERROR: No matching distribution found for torch==2.14.1+cpu
[RETRY] All 3 attempts failed
ERROR: build step 2 "gcr.io/cloud-builders/docker" failed: step exited with non-zero status: 1
```
Source confirmed in eph sandbox:
```
backend/requirements.txt:142: torch==2.14.1+cpu
```

## Root cause
The `+cpu` suffix is a *local version identifier*. CPU-only torch wheels with the `+cpu` tag are published only on PyTorch's own index (`https://download.pytorch.org/whl/cpu`), **not on PyPI**. The build's pip install uses the default PyPI index, so `torch==2.14.1+cpu` has no matching distribution. The base torch version 2.14.1 itself exists (it is listed in the "from versions" list), only the `+cpu` local variant is missing from PyPI.

## Fix validated
In the eph sandbox, the plain pin resolves on PyPI:
```
pip install --no-deps --dry-run 'torch==2.14.1'
  -> Downloading torch-2.14.1-cp311-cp311-manylinux_2_28_x86_64.whl (554.6 MB)
  -> Would install torch-2.14.1
```

## Recommended fix (E1 — source change in backend/requirements.txt, then redeploy)
Pick one:
- **Simplest:** change line 142 from `torch==2.14.1+cpu` to `torch==2.14.1`. Resolves directly from PyPI. Note the PyPI wheel is ~555 MB (includes CUDA deps), so the image is larger than a CPU-only build.
- **If a lean CPU-only wheel is required:** keep `torch==2.14.1+cpu` but the backend pip install must point at the PyTorch CPU index (e.g. `--extra-index-url https://download.pytorch.org/whl/cpu`). The platform build command does not add this index, so this path needs a build/pip configuration change rather than a plain requirements edit — prefer the simplest option above unless image size is a concern.
