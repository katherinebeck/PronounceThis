# RCA — Deploy run 51f56700-ce86-4c62-a71b-dede9e22b7c0 (accent-coach-pro)

## Summary
Redeploy failed at **build_image** (Cloud Build step #2 `docker-build`). The backend `pip install` of `/app/backend/requirements.txt` fails to resolve a pinned PyTorch version.

## Root cause (proven)
`backend/requirements.txt` line 142 pins:
```
torch==2.14.1+cpu
```
The `+cpu` local-version build only exists on PyTorch's own index (download.pytorch.org/whl/cpu). The build installs from pypi.org + the platform's CloudFront pip mirror, which only publish the plain wheel. pip therefore errors:
```
ERROR: Could not find a version that satisfies the requirement torch==2.14.1+cpu
(from versions: ... 2.13.0, 2.14.0, 2.14.1)
ERROR: No matching distribution found for torch==2.14.1+cpu
```
All 3 retry attempts failed → step #2 exits 1 → build_image fails before the image is produced.

## Verification
In an ephemeral sandbox on this run's source:
- `pip install --dry-run 'torch==2.14.1+cpu'` → same "No matching distribution" error (reproduced).
- `pip install --dry-run torch==2.14.1` → resolves cleanly (`Would install torch-2.14.1`, cp311 manylinux wheel, ~554 MB).

## Fix (Code — E1)
Edit `backend/requirements.txt` line 142. Drop the `+cpu` local tag:
```
torch==2.14.1
```
Then redeploy.

Note: the plain `torch==2.14.1` wheel is ~554 MB (CUDA-bundled); it resolves and builds, but inflates image size. If a slim CPU-only torch is desired, E1 would need to add PyTorch's CPU index (e.g. `--extra-index-url https://download.pytorch.org/whl/cpu`) to the install — but the minimal, build-unblocking change is simply removing `+cpu`.

## Not the cause
- Not a manifest fault (base image, entrypoint, nginx all fine; failure is pip resolving a user-pinned version).
- Not a secret/env, tier, or platform issue.
